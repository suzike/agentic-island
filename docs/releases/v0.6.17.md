# Agentic-Island v0.6.17

发布日期：2026-09-14

上一轮做开源对标的报告里，**截图工坊**列了一批提升项却一直没落地。这一版把它们补上，并顺手修掉一处浅色主题的对比度硬失败。

## 应用内框选：不再依赖 Windows 截图工具

点"截图工坊"或按 <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>S</kbd>，现在弹的是应用自己的框选叠层：

- 拖动出矩形，实时显示尺寸（**DIP 与实际物理像素都给**）
- 回车确认、Esc/右键取消、**只点一下不拖自动取消**（避免误触截整屏）
- 确认后由主进程先隐藏叠层，再让渲染层抓原生帧并按选区裁剪 —— 顺序不能反，否则暗底与选框会被拍进画面

这不只是体验问题：此前工坊的**唯一入口**是 `ms-screenclip:`，Windows 截图工具被策略禁用或系统被精简时，整个工坊进不去。现在系统工具只在叠层创建失败时兜底。

实测：框选 600×600 DIP → 成片 900×900 物理像素（150% 缩放），工坊直接拿到裁好的图。

## 滚动长截图

框选区域后自己往下滚：

- 应用按 260ms 抓帧，用**行指纹**自动对齐，只把新增的行追加到长图上
- **停手约 1.6 秒即自动完成**（不需要按任何键）
- 顶部小药丸实时显示"已拼接 N 帧 · 成图多少 px"，也可以随时点完成/取消

拼接引擎是纯逻辑、离线可验证。做法是"合成一张已知长图 → 切片成帧 → 拼回来逐像素比对"：

- 位移 40 / 137 / 260 / 480px 全部被准确测出；拼出的长图与原始高图**逐像素一致**
- 重复滚动（用户停下来又滚回去）不会把内容拼两遍
- 两帧之间**没有重叠**（滚太快）时如实计入"跳过"，而不是硬拼一张错位长图
- 另有长度上限与退化输入的兜底

三个实现要点都是测试逼出来的：探测带必须取**上半部**（滚过半屏时只有靠上的带子还在两帧重叠区里）、置信度按**能投票的带子**算（大位移天然只剩一条带子可匹配）、以及**测试图必须带行号相关的高频细节**（纯渐变在 8 位降采样后相邻行完全相同，位移会被测成差一行）。

## 钉屏、取色放大镜、零摩擦保存

- **钉屏截图**：一键把成片贴在所有窗口最上层，可拖动、滚轮调透明度、悬停出工具条（复制/关闭）；跟随显示器变化重定位，也纳入了"外部应用抢占时降层/复原"的窗口托管。
- **取色器 + 放大镜**：新增「取色/放大镜」工具，悬停出 15×15 像素的最近邻放大镜（标出光标所在格），旁边给色号、RGB、源图像素坐标，点击即复制。读的是**原图**像素而不是合成结果。
- **零摩擦保存（<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>S</kbd>）**：免对话框直接落到「图片/Agentic-Island」，并在同一次操作里把图放进剪贴板。

## 修复

浅色主题下「AI 造」按钮文字对比度实测 **2.79:1**（对比度审计硬失败）：它用了"中亮渐变 + 近白文字"，与设计系统的配对正好相反（`gradient.primary()` 是亮渐变配**深色**文字）。改用配对 token 后回到通过线以上。这是全仓唯一一处这种反向配对。

## 验证

typecheck 与两套 tsconfig、**42 个离线测试**（新增滚动截图拼接引擎）、对比度审计（硬失败 0）、`audit:ask`、`audit:terminal`、`audit:recording`（真录两段 + 真实点击注入 + 导出与成品自检）、NSIS 打包与 `verify:package`。

顺带记一笔排查结论：审计脚本自己在主屏铺的全屏活动窗口，会让 Chromium 在 150% 缩放的屏幕上把采集帧报成 **DIP 尺寸**。那是审计环境的副作用，不是产品回退——不经该窗口的真实录制实测成片是 2560×1600 原生。这条已写进审计脚本注释。

## 已知边界

截图工坊仍未做：批量美化、文字→美化卡片、本地离线 OCR、标尺/参考线。录屏侧：按键事件（键盘钩子需明确授权）、把光标美化移到导出期（需要应用内离线逐帧渲染）。
