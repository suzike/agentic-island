# Agentic-Island v0.6.19

这一版修的是 Agent 接入最影响可用性的阻塞问题：**岛把每次工具调用都误当成需要人审批**，导致 Claude Code / Codex 本来会自动执行的 Bash、MCP、编辑工具也被 `PreToolUse` 挂住，最长等待 600 秒。

现在，`PreToolUse` 只上报活动；只有 CLI 真正准备弹授权提示时，才由 `PermissionRequest` 接管。

## 修复内容

- **`PreToolUse` 零阻塞**：只记录工具活动，不返回权限决定。普通工具调用继续走 Claude Code / Codex 自己的权限系统；活动上报最多等 2 秒，桥卡住也快速 fail-open。
- **只在真正需要授权时弹窗**：`PermissionRequest` 只在 CLI 准备弹权限提示时触发。自动放行的工具不会进入岛，不会出现“调个工具就弹窗”。
- **岛内批准真正回传 CLI**：Claude Code 使用 `hookSpecificOutput.decision.behavior=allow/deny`；Codex 使用同一套原生 `decision.behavior`，删除会被判失败的旧字段。
- **计划批准不再二次询问**：`ExitPlanMode` 批准时额外回传原始 `updatedInput`，Claude Code 会直接采用岛内裁决。
- **拒绝理由回传模型**：deny 使用 `decision.message` 返回理由，Agent 可据此调整。
- **清理重复权限 hook**：安装器移除历史遗留的 `agentic-island-permission.mjs` 条目，避免一次 Codex 授权发两条请求、弹两张卡。
- **Codex hook 路径稳定**：命令统一使用正斜杠，避免应用重启后因 `C:\...` / `C:/...` 变化触发信任哈希失效。

## 验证

- `npm run typecheck`：两套 tsconfig 通过。
- `npm test`：**42 个离线脚本全部通过**；新增覆盖 `PreToolUse` 不阻塞、`PermissionRequest` allow/deny、计划 `updatedInput`、桥卡死 2 秒 fail-open、Codex 同协议与安装器幂等。
- `npm run build`：主进程 / preload / renderer 生产构建通过。
- `npm run audit:contrast`：硬失败 **0**，小字号复核 0；83 条弱化层级样本单独列出。
- `npm run audit:ask`、`npm run audit:terminal`、`npm run audit:screenshot`：隔离 Electron 审计通过。
- `npm run audit:recording`：真录合成 + 原始两段，真实点击注入，导出成品 `1080×1920 · 30fps · H264`，自检通过。
- 真实 Codex CLI：全局 hook 状态为 `trusted`；`PreToolUse` 只产生活动、不再等待审批；桥“接受连接但不响应”时实测 2.1 秒 fail-open。
- 未验证项：本机 Claude CLI 的 OAuth 已过期，无法在本轮重新执行真实 Claude 模型工具调用；Claude 侧按官方 hooks 协议与离线回归覆盖，需在有效登录环境中做一次真实 CLI 复核。
