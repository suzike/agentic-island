# Agentic-Island v0.6.16

发布日期：2026-09-14

这一版先修掉"录屏与截图不够清晰"，再把鼠标点击纳入事件日志，并补齐导出期运镜的跨画幅与成品自检。

## 录屏模糊的根因是默认设置，不是采集能力

2560×1600 的屏，采集默认 `1080p` + `16:9` + `完整显示`：16:10 的画面按高度缩进 1920×1080 画布、还要补左右黑边，**实际内容只有 1728×1080（约原生的 67%）**，全屏回放再放大 1.48 倍 —— 小字必糊。

现在默认**跟随屏幕原生 + 跟随源画幅**，三个场景预设也不再偷偷降级（它们该区分的是帧率/画质/运镜/音频，而不是把画面缩小）。实测同样操作：成片从 1920×1080 变成 **2560×1600**。

采集链路本身是好的：实测 Chromium 抓 2560×1600 与 DPI-aware 的 .NET 直接抓物理像素**逐像素一致**（锐度 35.2983 == 35.2983）。

## 截图：修掉一次隐性重采样，以及"抓错屏"

- **每次都被多一次重采样**：逻辑尺寸 1707×1067 × scaleFactor 1.5 = 2560.5，取整成 **2561×1601** 去请求缩略图，而面板是 2560×1600 —— 同一张静态图锐度实测 84.9 → 64.1。现在"整屏"改走**媒体流**（与录制同一条链路）取原生帧，尺寸不经过任何取整与缩放，实测抓回 2560×1600。
- **静默抓错屏**："光标所在显示器"匹配不上时会退到 `sources[0]`，连拍 5 张实测 1 张是副屏。现在重试一次，仍不匹配就明确报错。

需要说明：截图工坊标题那个入口走的是 **Windows 自带截图工具 + 剪贴板**，应用侧读取实测无损（2560×1600 进、2560×1600 出）；那条路的画质由 Windows 决定。

## 鼠标点击事件采集（只鼠标、只在录制期间）

光标轨迹只能说明"人在动"，说明不了"点了哪里"；点击是**事后无法补录**的信号。现在录制期间采集左/右/中键点击并落进工程，最直接的收益是**剪除空白不再误剪"盯着看并且点了"的片段**（翻页、逐条点开时每秒都点一下，纯看轨迹会把整段判成发呆），同时为后续的点击涟漪、按点击自动推近留好数据。

三条边界是刻意的：① 只监听鼠标点击，**不碰键盘**；② 只在录制期间装钩子（录屏时那块屏幕本来就在被逐像素记录，不引入新的隐私面），停止录制即卸载；③ 原生模块缺失时静默降级，录屏照常。审计会真的注入一次系统级点击，断言它落进了工程。

## 导出：成品自检、跨画幅运镜、画幅重组

- **导出后自检**：导出完成不再只报"已导出"，而是读回写出的文件与请求对照 —— `已导出 … · 自检通过（8.8s · 30fps · H264）`。本项目被"导出画面飞快跑完"咬过两次，两次都是文件写成功、只有内容不对，所以"导出完成"必须以读回来的元数据为准。顺带修掉导出链路的静默失败。
- **跨画幅也能运镜**：先按目标画幅"铺满"裁齐，再把光标轨迹重映射进裁切后的画框，所以竖屏 + 运镜可以同时用（实测 2560×1600 素材 + 竖屏画布 → 成片 1080×1920）。
- **原始画面采集不再被画面比例挡住**：导出页有了自己的「画布」档（跟随素材 / 横屏 / 竖屏 / 方形），补黑边或裁切由导出期完成。
